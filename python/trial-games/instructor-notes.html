可选游戏实验：选一个规则，亲手改一次

八个独立挑战 · 英文学生任务、中文带课提示 · 原 50 分钟核心课仍为七轮

怎么安排，不把试听课塞满

  • 核心七轮不增加必做任务。提前完成当前阶段的学生，可以独立选一个 3–5 分钟挑战；继续保留最后的成果分享与下载时间。
  • 8–12 分钟任务适合课后继续或老师预先安排的拓展时间。12–20 分钟任务适合加时或下一次游戏实验课，不要求所有零基础学生当堂完成。
  • 一次只选一个任务。完成标准是“预测 → 改一处 → 运行 → 指出变化 → 解释”，不是浏览所有卡片。
  • 新手优先选择 Draw your mascot、Set the ball speed 或 Dice showdown；熟练学生再尝试按键、碰撞、分支或游戏结束规则。
  • 连续动画的更新、绘图和碰撞代码是提供的脚手架。学生应能解释自己的修改，不需要第一次就读懂全部代码。

课前检查与游戏操作

  • 提前运行一个静态绘图和一个按键任务，确认浏览器已加载游戏运行环境，画面与状态面板都能更新。
  • 说明 Run 会从代码中的初始状态重新开始；Stop 用于立即结束当前运行。编辑后需重新 Run，才能把观察结果对应到最新代码。
  • 按键前先聚焦游戏区域。触屏学生使用屏幕上的方向按钮；不要把设备或操作熟练度差异当作学习差异。
  • 先保留原版运行的观察，再改一个参数重跑。速度比较应保持起点与其他参数相同，浏览器卡顿时只作定性描述。
  • 图形任务使用 pygame 和课程提供的更新／绘图入口。普通 Python 的骰子与猜数任务可单独运行和逐步可视化；不要把图形脚手架当作所有 Python 环境都内置的功能。
  • 不需要安装本地 Python、素材包或额外帐号；若设备暂时无法运行，让学生在同伴设备上轮流操作，自己的预测与修改仍由本人完成。

网页如何运行 pygame

本页使用 pygame-ce 的浏览器版本，由 Pyodide 执行真实 Python。import pygame、绘图和矩形碰撞来自游戏库。课程提供画布、方向控制，以及反复调用 update(dt, keys) 和 draw(screen) 的运行脚手架；学生不用先编写主循环。

  • 游戏区域为 480 × 320；x 向右增加，y 向下增加。dt 是本次更新的秒数；keys 记录当前按下的方向名称。
  • 这些示例使用简单图形，无需上传图片或声音。第一次运行会加载游戏工具，建议课前先试跑。
  • 普通 Python 练习本可保留游戏代码副本并用于提问，但运行这些图形任务应回到游戏页。骰子与猜数任务不依赖图形库，可使用普通 Python 运行和可视化。
  • 桌面 pygame 项目可能自带窗口、事件循环、图片、声音或其它依赖，不能保证原封不动粘贴到这里就能运行。先使用本页给出的两个函数入口。

Draw your mascot

零基础首选，3–5 分钟即可。只要求改一个坐标并说出方向，不展开坐标系证明或全部绘图参数。学生先运行原版再改 x，指出整张脸一起移动的证据。进阶者一次只改颜色或 y，再尝试添帽子；不要要求画得漂亮或使用真实姓名。

学生任务
Run the starter to meet your mascot. The provided drawing lines make its face. Choose a new x value, then run your edited code.
先预测
When x gets larger, which way will the whole face move?
这次只改什么
Change only x from 120 to 260. Run again and compare the position.
可观察的完成证据
The whole face moved right; its eyes and mouth stayed with it. Point to the value you changed and explain the visible effect.
遇阻时的一条提示
x increases toward the right; y increases downward. The eye positions use x too, so they move with the face.
进一步探索
Make a second experiment: change color or y, one at a time. Then add a rectangle for a hat using the provided drawing pattern.

Set the ball speed

适合第一次看到动画的学生。速度单位是像素／秒，dt 是引擎提供的每次更新时间；不要求新手推导或编写循环。每次比较必须重新 Run，让起点一致。只需观察快慢，不把网络卡顿下的秒表读数当精确实验。负速度需先补左边界规则，避免把跑出画面误认为程序没有执行。

学生任务
Watch the ball travel across the canvas and wrap back to the left. Stop it, edit speed, and run from the same starting position.
先预测
If you double speed, what will change about the trip across the canvas? What will stay the same?
这次只改什么
Change only speed from 100 to 200. Run again from the starter position.
可观察的完成证据
The edited ball crosses the same canvas faster. Its radius, color, and travel direction stay the same. Explain which line uses speed.
遇阻时的一条提示
The supplied update function runs repeatedly. speed * dt adds the distance traveled during one short update.
进一步探索
Try speed = 0 and explain the result. Then add a left-edge wrap rule before experimenting with a negative speed.

Dice showdown

这是普通 Python 任务，可用逐步可视化观察分支。每次运行会重新抽随机数，不要求两次结果相同，也不能用胜负作为完成评价。检查取值范围与学生对随机性的解释。若延伸到公平性，强调改成 12 面只改变分布，不能凭一两局胜负证明游戏公平或不公平。

学生任务
Run the program several times. Each run rolls one die for you and one for the bot. Then experiment with a different number of sides on your die.
先预测
Must the same code show the same rolls each time? What values would a twelve-sided die allow?
这次只改什么
Change only my_sides from 6 to 12. Run several times and record actual rolls, including a loss or tie if one happens.
可观察的完成证据
Your rolls stay between 1 and 12; the bot’s stay between 1 and 6. You can explain why changing the rule does not guarantee a win on every run.
遇阻时的一条提示
random.randint(1, 12) can return any whole number from 1 through 12, including both ends. A bigger die can still roll a small number.
进一步探索
Restore equal dice and use a supplied for-loop pattern to record ten rounds. Count wins, losses, and ties; explain why ten rounds do not establish an exact long-run win rate.

Collect the coin

先让学生试玩成功一次，再改速度。重点是区分移动规则与计分规则，不要求讲解整段按键与边界代码。新手可只改 speed，熟练者再改每枚金币的分值。确认金币接触后移开，学生观察的是一次收集的一次加分；不要按收集速度排名。

学生任务
Run the game, focus the game area, and use the arrow keys or on-screen controls to reach the gold coin. Collect it once before editing.
先预测
If you increase player speed, will each coin be worth more points?
这次只改什么
Change only speed from 140 to 220. Restart, collect a coin, and compare the movement and score rule.
可观察的完成证据
You can move the blue player, collect a coin, and find score in the state panel. Each collected coin adds one point even after the speed edit.
遇阻时的一条提示
The arrow-key lines move the player. colliderect checks whether the player and coin rectangles overlap. score += 1 changes the score.
进一步探索
In a separate experiment, change the reward from 1 to 5. Explain how a rule change differs from a movement change.

Build a bounce wall

这是有意的逻辑错误，不是 pygame 加载故障。先观察球卡在右边界，让学生指出该处应向左，再只改右边的一行。用 vx 正负号解释，避免把 abs、两个 if 或全部绘图一次讲完。伸展任务涉及二维运动，可留到下次。

学生任务
This game has one deliberate bug. Run it and observe the ball at the right wall. Compare the two wall rules, then repair the direction.
先预测
At the right wall, should vx point right or left? What sign would make x decrease?
这次只改什么
Change only the right-wall assignment from vx = abs(vx) to vx = -abs(vx). Keep the left-wall assignment unchanged.
可观察的完成证据
The repaired ball reverses at the right wall and later at the left wall. In the state panel, vx changes sign when the ball reverses.
遇阻时的一条提示
abs(vx) is a nonnegative speed. -abs(vx) makes it negative. Adding a negative change makes x smaller.
进一步探索
Add a separate y velocity and top/bottom wall rules. First predict the sign needed at each wall.

Guess the number

这个任务练习系统测试，不是保密竞猜：secret 在代码中可见。要求学生分别设计小于、等于、大于三种输入并留下实际结果。可借可视化看未执行的分支。浏览器输出框不是输入终端，直接修改 guess 后重跑；不要要求学生使用 input()。

学生任务
This practice game keeps the secret visible so you can test every rule. Edit guess and run each attempt; you do not need to type into the output box.
先预测
With secret = 7 and guess = 4, which message will appear? Which guess would test the equality branch?
这次只改什么
Change only guess. Run once with a value below 7, once equal to 7, and once above 7. Record which branch each test reaches.
可观察的完成证据
Your three intentional tests produce “Too low”, “You found the number!”, and “Too high”. Explain why just one branch runs per attempt.
遇阻时的一条提示
Python checks if first, then elif when needed. else handles the remaining case. Keep the indentation of the supplied messages.
进一步探索
Use Visualize to follow the selected branch. Then add a valid range from 1 to 10 and give an out-of-range guess a separate message.

Keep it up!

适合已有变量或分支经验的学生，或作为课后 12–20 分钟任务。新手只需改球拍宽度并解释可接触面积，完整碰撞与循环是脚手架，不要求默写。试玩成绩受操作熟练程度影响；比较参数作用，不据一局得分声称某设置一定更好。必须测试接住、漏球和重新 Run。

学生任务
Run and move the paddle with left/right controls. A catch bounces the ball and increases hits. A miss ends the round. Run again to restart.
先预测
What might a wider paddle change? Will changing its width automatically change the ball speed?
这次只改什么
Change only paddle_width from 80 to 140. Start a new run and compare. Keep both ball velocities unchanged.
可观察的完成证据
Show a successful bounce, a miss, and a fresh restart. Explain that paddle width changes the contact area while vx and vy still set the ball velocities.
遇阻时的一条提示
Watch hits and alive in the state panel. The supplied collision code bounces a falling ball when its rectangle touches the paddle.
进一步探索
Add a controlled speed increase after a catch, or add three lives. Keep restart behavior clear and test both a catch and a miss.

Meteor dodge

高阶可选任务，建议课后或延长游戏实验课再做。检查一次碰撞是否结束、时间是否停止、重新运行是否清零，不能只看能否躲开。陨石位置采用固定规则，便于讨论“只改一个参数”；可见图形是碰撞矩形而非精确物理模型。增加生命时必须处理持续重叠导致连续扣血的情况。

学生任务
Move the blue player left or right while the meteor falls. A collision stops the round. Read seconds and alive in the state panel; Run again starts a fresh round.
先预测
If meteor_speed increases while player_speed stays fixed, what part of the game changes?
这次只改什么
Change only meteor_speed from 100 to 160. Restart and observe its fall. Keep player_speed and the other rules unchanged.
可观察的完成证据
Show movement, a collision ending the round, and a restart with seconds near zero and alive set to True. Explain which speed you changed and which you kept fixed.
遇阻时的一条提示
meteor_y increases as the obstacle falls. When alive becomes False, update returns before moving anything or adding time.
进一步探索
Add three lives or a second meteor. Decide how to avoid subtracting a life on every update while shapes still overlap.

老师巡视时只追问三件事

  1. “你预测改这个数字后，哪里会变？”
  2. “你这次只改了哪一处？其余什么保持不变？”
  3. “哪一个画面、状态值或真实输出支持你的解释？”

学生卡住时，先请他指出修改的代码，再观察结果或读错误末行。给一个最小提示后把键盘交回学生。随机胜负、反应速度、通关或最高分都不能代替对代码的理解。

收尾与故障处理

  • 成果至少保留任务名称、预测、个人修改后的代码，以及一句来自实际运行的观察。保存后重新 Run，核对结果与代码一致。
  • 没有真正运行时，明确写“预测／待验证”，不要把示例检查点当作自己已取得的结果。
  • 静态图能运行而按键无效时，先检查焦点与屏幕方向按钮。方向键卡住时停止并重启，再检查按键释放。
  • 游戏库加载失败时，可先用骰子或猜数两个普通 Python 任务继续，稍后再回到图形任务。
  • 实时课堂分享仍由学生自愿加入；状态与文字输出不能代表老师已看到学生完整游戏画面。请学生口述观察，必要时自愿展示自己的设备。
  • 不强制 Zoom 屏幕共享、AI 分析或公开学生真实姓名。
