The Story

Why we call it "regression"

In the 1880s, Francis Galton measured the heights of hundreds of parents and their grown children. He noticed that very tall parents tended to have tall children — but slightly closer to average. Heights "regressed toward the mean." The line he drew through that cloud of points gave us the name for the whole method we still use today: regression.
Neural voice · click to play / pause

The METHOD outlived the specific finding — "regression" stuck as the name for "fit the best line through a cloud of points," whatever the cloud is about. Today's cloud: box height and distance.

The name's origin is a fun etymology fact AND a real statistical phenomenon (regression to the mean shows up everywhere: sequels, sophomore slumps, second test scores). Keep it brief — the point is just that fitting-a-line-through-a-cloud is 140 years old and still exactly what we do.
Concept 1 · the shape of the problem

Features → target

📥 Features (X)

What you already know — box height in pixels, hours studied, square footage. Class 8 called these "columns"; here they're the model's inputs.

🎯 Target (y)

What you want to predict — distance in meters, a test score, a price. A number, not a category (that's Class 11).

KEY IDEA — a model is just a learned relationship between features and a target. Regression finds the line (or hyperplane, with more features) that describes that relationship best. "Best" gets a precise meaning next.
Deliberately simple framing before the math arrives. 'Hyperplane' gets one clause, not a slide — multi-feature regression is a backup topic, not core material today. The X/y notation is worth writing on a literal board if teaching in person; it recurs through Class 13.
Concept 2 · the idea in one picture

Loss: how wrong are we?

"Best fit" means smallest error. Loss (here, Mean Squared Error) measures total wrongness — training nudges the line to make loss as small as possible.

MSE = mean( (y_true − y_pred)² )

Squaring does two jobs: it kills the +/− sign problem, and it punishes big misses harder than small ones.

Look at the numbers: the too-flat and too-steep lines have huge SSE (~52-53); the OLS best-fit line's SSE is a fraction of that (~5). Lower loss isn't always better — overfitting (Class 3!) is what happens when a model chases loss all the way to zero by memorizing noise instead of learning the trend.
The SVG is computed live from real coordinates and a real OLS formula — not eyeballed. Walk the three lines: the bad ones are visibly worse AND numerically worse, which is the whole point of loss as an objective measure. The overfitting caveat is a callback, not new content — keep it to one sentence.
Check · reading loss

Quick check · tap an answer

Two candidate lines fit the same cloud of points. Line A has SSE = 12. Line B has SSE = 340. Which line does the data prefer, and why?

Loss measures total wrongness — lower is better. SSE 12 means the line's predictions land close to the real points; SSE 340 means they're far off. Training is the search for the parameters that make this number as small as reasonably possible.

A pure vocabulary check before gradient descent needs it. If this misses, pause here — everything from here assumes 'lower loss = better fit' is second nature.
Concept 3 · how a model actually learns

Gradient descent: walking downhill blindfolded

Picture the loss for every possible (m, b) as a landscape of hills and valleys. Training starts somewhere on that landscape and takes small steps downhill — toward lower loss — until it reaches the valley floor.

  • At your current spot, compute the gradient: which direction is steepest uphill
  • Step the opposite way — downhill — by a small amount
  • Repeat, thousands of times, until the loss stops dropping
⛰️➡️🏔️

Mountain-descent analogy:
eyes closed, feel which way is downhill, take a step, repeat — you'll reach the bottom without ever seeing the whole mountain.

The step size is the learning rate. Too small: painfully slow. Too large: you overshoot the valley and bounce around — or never converge at all. Lab 1 today: you implement this exact loop yourself, from scratch.
The mountain analogy is doing real work — it's the intuition for EVERY optimizer in this course and in deep learning generally (Pattern decks reference gradient descent too). Learning-rate too-big/too-small is worth a live show-of-hands: 'who's ever taken steps so big they overshot something?' Lab 1 makes this concrete in ~15 lines of Python.
Concept 4 · the honest number, again

Train on some, judge on the rest

📚 Train

The examples the model sees and learns from — gradient descent adjusts m and b against this pile only.

🔒 Test

Examples the model has never seen. Scoring here is the only honest measure of whether it actually learned the pattern — or just memorized the training rows.

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25)
Recognize this? It's Class 3's three-pile discipline, back for its first real workout: train to fit, test to judge. Score on training data and you're measuring memorization, not learning — the same trap the overfitting quiz warned about two classes ago.
Deliberately framed as "nothing new," which is true — this reinforces that the discipline from Class 3 wasn't abstract, it's what every model class from here on actually does. Validation pile formally reappears in Class 14; today two piles (train/test) is enough.

Reference · key terms

Today's vocabulary

Feature / target — what you know (input) vs. what you predict (output). X and y.

Loss (MSE) — mean squared error: how wrong the model's predictions are, on average.

Gradient descent — repeatedly stepping downhill on the loss landscape until it stops falling.

Learning rate — the size of each downhill step; too big overshoots, too small crawls.

R² (R-squared) — the fraction of the target's variation the model explains; 1.0 is perfect, 0 is no better than guessing the average.

Extrapolation — predicting outside the range of training data; a line has no edges, so it will answer anyway — often wrongly.

R² gets its first formal definition here (it's appeared unglossed since Class 3's lab). Extrapolation is today's most important new word — it recurs whenever a model is asked about data unlike anything it trained on.

Today's line to remember

"All models are wrong, but some are useful."

— George E. P. Box, statistician

Your line isn't reality — it's a simplification that works within its range, and breaks honestly outside it.

The canonical quote for this exact lesson — Box coined it about statistical models generally, but nothing captures today's extrapolation lab better. A "wrong" model (a straight line through a probably-curved reality) was still USEFUL within its training range. That distinction is the whole hour.
Wrap-up

Three things to keep

  • A model is a learned relationship: features in, a target predicted out
  • Loss measures wrongness; gradient descent walks downhill until it stops falling
  • Judge on test data only — and never trust a prediction far outside the training range

Backup · beyond one feature

Multiple regression: more inputs, same idea

One feature

distance = m·box_height + b

A line through a 2D cloud (height vs. distance).

Many features

distance = m₁·box_height
   + m₂·box_width + b

A flat plane (or hyperplane) through a higher-dimensional cloud — one weight per feature.

The code barely changes — X just gets more columns. Each coefficient answers "holding everything else fixed, how much does THIS feature move the prediction?" — exactly what demo 2's AI coefficient-reader was interpreting.
Answers the question sharp students ask within the first ten minutes: "can't we use more than one feature?" Yes, trivially — sklearn's API doesn't change shape. The per-coefficient interpretation callback ties back to demo 2.
Backup · a preview, not a full lesson

What if the model tries too hard?

The problem

With many features, plain regression can assign huge weights to noisy columns — memorizing quirks instead of the real trend. Sound familiar? It's overfitting (Class 3), wearing a regression costume.

The idea (Ridge / Lasso)

Add a penalty for large coefficients to the loss. The model must now justify every big weight — smaller, steadier coefficients that generalize better to the test set.

You don't need the math today — just the shape of the idea: penalize complexity, not just error. This is the family of fixes that answers Lab 2's Challenge 2 ("what would you add before shipping this?").
Deliberately kept conceptual, no formulas — the goal is name recognition (Ridge, Lasso) and the "penalize complexity" intuition, which resurfaces properly if the course ever reaches deep learning regularization. Directly answers the lab's own challenge question.
