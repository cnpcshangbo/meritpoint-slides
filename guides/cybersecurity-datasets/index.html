1Choose your data starting point

Research readiness is our editorial assessment of provenance, documentation, reproducible access, student tractability, and a safe starting point. It is not a certification of data truth or model performance.

Network intrusion●●●●○

CIC-IDS2017

Canadian Institute for Cybersecurity

Five days of network traffic; PCAP and labeled CSV files; 80+ flow features; DDoS, botnet, scanning, web attacks, and more.

Safe starting pointDownload MachineLearningCSV first and compare a day-based split with a random split.

Read the limitation: It represents one experimental network in 2017; a high score does not prove generalization to today's traffic.

Network intrusion●●●●○

CSE-CIC-IDS2018

CIC + CSE

A larger enterprise-network scenario with raw traffic, flow features, and several common attack families.

Safe starting pointBegin with one day or one attack family, then report binary classification and the false-positive rate.

Read the limitation: The files are large; check label and feature-file consistency before modeling.

Open official data page ↗
Network intrusion●●●●○

UNSW-NB15

UNSW Canberra Cyber Range Lab

2,540,044 records, 49 features, nine attack categories, official train/test files, and raw PCAP traffic.

Safe starting pointUse the official CSV split first; compare logistic regression, random forest, and a calibrated threshold.

Read the limitation: Normal traffic and some attacks were generated in a testbed; the official split is not a deployment environment.

Open official data page ↗
Malware files●●●●○

EMBER 2018

Elastic Security Research

A classic static-feature benchmark for Windows PE (Portable Executable) files such as .exe and .dll, with feature-extraction code and baseline models.

Safe starting pointTrain LightGBM directly on the extracted features; do not download or execute malware binaries.

Read the limitation: The file format and time period are narrow, and random splits can overstate future performance.

Open official data page ↗
Malware files●●●●●

EMBER2024

FutureComputing4AI

3.2 million benign and malicious files across Win32, Win64, .NET, APK, ELF, and PDF, with seven label or tag groups.

Safe starting pointChoose one file type and vectorized features first, then test cross-format or temporal generalization.

Read the limitation: The scale and task range are large; define one label, format, and metric before downloading.

Open official data page ↗
Malware files●●●●○

SOREL-20M

SophosAI + ReversingLabs

Large-scale Windows PE features, labels, and metadata suited to weak supervision and label-noise studies.

Safe starting pointBegin with a pre-extracted feature subset and report PR-AUC plus recall at a low false-positive rate.

Read the limitation: Twenty million files are too large for most first projects; estimate storage and compute before scaling up.

Open official data page ↗
Malware files●●●●●

BODMAS

UIUC + Blue Hexagon

134,435 feature vectors, 2,381 static features, 2019–2020 timestamps, and 581 malware families.

Safe starting pointSort by time, train on earlier months, and measure how quickly performance declines.

Read the limitation: Raw malicious binaries have access restrictions; student projects should prefer the public features and metadata.

Open official data page ↗
Android●●●○○

AndroZoo

University of Luxembourg

A continuously growing Android APK collection from Google Play and other sources, with multi-engine antivirus metadata.

Safe starting pointUse metadata or a mentor-provided static-feature table; analyze APKs only in an isolated environment.

Read the limitation: Access is conditional, and antivirus-consensus labels can change over time.

Open official data page ↗
Threat intelligence●●○○○

MalwareBazaar

abuse.ch

Continuously updated real-world malware samples and metadata for observing emerging threats and distribution shift.

Safe starting pointUse only the public metadata or API for statistics; never download or run samples on a personal computer.

Read the limitation: Live malware is high risk and labels can be incomplete; sample work needs a mentor, sandbox, and institutional process.

2Turn data into a research question

Every question includes data, suggested figures, and one defensible contribution. Choose one, then put time, device, network, or family into the experimental split.

QN-01StarterNetwork intrusion

How much do intrusion-detection scores change between random and day-based splits?

Data: CIC-IDS2017

Suggested figures: Random-vs-time F1 and PR-AUC bars · day-based confusion matrix

Defensible contribution: Separates leakage-inflated scores from genuine temporal generalization.

QN-02StarterNetwork intrusion

Can ten flow features retain most of the attack-detection performance?

Data: UNSW-NB15

Suggested figures: Performance vs feature-count curve · feature importance

Defensible contribution: Produces an interpretable accuracy–cost curve for a lightweight IDS.

QN-03SolidNetwork intrusion

Which attack types does the model confuse most often?

Data: CIC-IDS2017

Suggested figures: Normalized confusion matrix · per-class recall

Defensible contribution: Replaces one overall score with an actionable map of failure modes.

QN-04SolidNetwork intrusion

Does a model trained on one intrusion dataset work on another?

Data: CIC-IDS2017 + UNSW-NB15

Suggested figures: Cross-dataset performance matrix · feature-shift plots

Defensible contribution: Quantifies the generalization gap across networks and collection pipelines.

QN-05SolidNetwork intrusion

How many attacks are detected when the false-positive rate must stay below 1%?

Data: CSE-CIC-IDS2018

Suggested figures: Zoomed ROC region · threshold–recall curve

Defensible contribution: Translates model performance into an alert volume a security team could tolerate.

QN-06StretchNetwork intrusion

Can a model say ‘I don't know’ when it sees an attack class absent from training?

Data: UNSW-NB15

Suggested figures: Risk–coverage curve · unknown-class score distribution

Defensible contribution: Tests open-world recognition instead of forcing a confident guess.

QN-07SolidNetwork intrusion

Does class resampling improve rare-attack detection or merely move the errors?

Data: CIC-IDS2017

Suggested figures: Precision–recall curves · per-class errors before and after resampling

Defensible contribution: Tests whether a common class-imbalance recipe actually helps.

QN-08StretchNetwork intrusion

How much performance disappears after removing IP, port, and time clues?

Data: CIC-IDS2017

Suggested figures: Ablation table · feature-group performance bars

Defensible contribution: Tests whether the model learned attack behavior or memorized the laboratory.

QM-01StarterMalware files

How quickly does a malware detector decay after several months?

Data: BODMAS

Suggested figures: Monthly AUC and PR-AUC curves · monthly sample counts

Defensible contribution: Measures concept drift directly with a chronological split.

QM-02StarterMalware files

Which baseline gives the best accuracy–speed trade-off: logistic regression, random forest, or LightGBM?

Suggested figures: Performance vs training-time scatter · confusion matrix

QM-03SolidMalware files

Data: EMBER2024

QM-04SolidMalware files

Which malware families are hardest to distinguish—and is the cause sample scarcity or feature similarity?

Data: BODMAS

Suggested figures: Family confusion matrix · sample count vs F1

QM-05StretchMalware files

How much do uncertain or conflicting labels harm malware training?

Data: SOREL-20M

Suggested figures: Curves by label confidence · noise-sensitivity plot

Defensible contribution: Quantifies the cost of label noise in real threat intelligence.

QM-06SolidMalware files

Can interpretable behavior tags retain performance close to a black-box detector?

QM-07SolidMalware files

Data: EMBER 2018 + BODMAS

Suggested figures: Within-source vs cross-source table · distribution-shift plot

Defensible contribution: Measures temporal and collection-source generalization together.

QM-08StretchMalware files

Data: EMBER2024

3Three recommended starting routes

Route A · Your first intrusion-detection study

  1. Use the official UNSW-NB15 train/test CSV files
  2. Logistic regression as an interpretable baseline
  3. Random forest as a nonlinear comparison
  4. Report PR-AUC, per-class recall, and performance at 1% false positives

Route B · Temporal-drift study

  1. Use BODMAS public features and timestamps
  2. Split by month or quarter; never shuffle time
  3. Plot performance against months since training
  4. Separate decline from new and previously seen families

Route C · Cross-platform malware

  1. Choose two EMBER2024 file formats first
  2. Build one model per format
  3. Compare with one shared model and cross-format transfer
  4. Report negative transfer and abstention limits

4Sources and use notes

  • The official UNSW page confirms 2,540,044 records, 49 features, nine attack categories, and official train/test files.
  • The EMBER2024 repository confirms 3.2 million files, six file types, and seven label or tag groups.
  • The BODMAS project page confirms timestamps, family information, 134,435 vectors, and a public feature download.
  • The AndroZoo page confirms a growing, multi-source Android APK collection with conditional access.
